# Builder Architecture

The builder layer enforces structural correctness at compile time. Each builder
produces a specific Ruby file layout where the section ordering, nesting, and
content are guaranteed by the Rust type system.

## Design Principle

The builders use the **typestate pattern** -- different builder types expose
different operations. You cannot call `.attribute()` on a `TypesFileBuilder`
directly; you must be inside a `.class()` closure, which gives you a `ClassBuilder`
where only `.attribute()` is available.

```
TypesFileBuilder ---.class()--> ClassBuilder ---.attribute()--> ClassBuilder
                                                                  |
ResourceFileBuilder ---.map()/.map_present()/.map_bool()--> ResourceFileBuilder
                                                                  |
RSpecBuilder::describe() --> DescribeBuilder ---.it()--> ItBuilder
                                               .context() --> DescribeBuilder
                                               .let_bind()
                                               .it_behaves_like()
```

## TypesFileBuilder

### Guaranteed Structure

Every `TypesFileBuilder.emit()` output has this exact section ordering:

```
1. # frozen_string_literal: true
2. # Code generated by pangea-forge. DO NOT EDIT.
3. (blank)
4. require 'pangea/resources/base_attributes'
5. (blank)
6. module Pangea::Resources::{Provider}::Types
7.   include Dry.Types()
8.   (blank)
9.   class {ClassName} < Pangea::Resources::BaseAttributes
10.    T = Pangea::Resources::{Provider}::Types
11.    (blank)
12.    attribute :name, Type
13.    ...
14.  end
15. end
```

This is not convention -- it is structurally enforced. The builder constructs
a fixed `Vec<RubyNode>` with the pragma, comment, require, and module wrapper
hardcoded. Classes and attributes are inserted into the module body.

### Provider PascalCase

The builder handles provider name conversion internally:

| Input | PascalCase | Override reason |
|-------|-----------|----------------|
| `"aws"` | `"AWS"` | All-caps acronym |
| `"gcp"` / `"google"` | `"Google"` | Normalized |
| `"azurerm"` | `"Azure"` | Terraform-specific prefix stripped |
| `"porkbun"` | `"Porkbun"` | Standard capitalize |
| `"my_provider"` | `"MyProvider"` | Underscore to PascalCase |

### ClassBuilder Restriction

`ClassBuilder` exposes exactly one method: `.attribute(name, type, required)`.
You cannot:

- Add a module inside a class
- Add a require inside a class
- Add a class inside a class
- Add a registry call inside a class

The Rust type system prevents all of these -- `ClassBuilder` simply does not have
those methods. The closure `|c: ClassBuilder| -> ClassBuilder` returns a builder
with accumulated attributes, and the parent `TypesFileBuilder` wraps them in the
correct `RubyNode::Class` structure.

### Multi-Class Support

`TypesFileBuilder` supports multiple classes in a single types file:

```rust
TypesFileBuilder::new("aws")
    .class("VpcAttributes", |c| {
        c.attribute("cidr_block", RubyType::simple("T::String"), true)
    })
    .class("SubnetAttributes", |c| {
        c.attribute("vpc_id", RubyType::simple("T::String"), true)
         .attribute("cidr_block", RubyType::simple("T::String"), true)
    })
    .emit()
```

Each class gets its own `T = Pangea::Resources::{Provider}::Types` constant.
This is proven: the number of `T = ` assignments always equals the number of
`class` declarations (tests/structural.rs proof 11, tests/compiler_guarantees.rs proof 15).

## ResourceFileBuilder

### Guaranteed Structure

Every `ResourceFileBuilder.emit()` output has this exact layout:

```
1. # frozen_string_literal: true
2. # Code generated by pangea-forge. DO NOT EDIT.
3. (blank)
4. require 'pangea/resources/base'
5. require 'pangea/resources/reference'
6. require 'pangea/resources/{tf_type}/types'
7. require 'pangea/resource_registry'
8. (blank)
9. module Pangea::Resources
10.   module {ProviderResource}
11.     include Pangea::Resources::ResourceBuilder
12.     (blank)
13.     define_resource :{tf_type},
14.       attributes_class: {Provider}::Types::{Resource}Attributes,
15.       outputs: { id: :id },
16.       map: [:field1, :field2],
17.       map_present: [:field3],
18.       map_bool: [:field4]
19.   end
20.   module {Provider}
21.     include {ProviderResource}
22.   end
23. end
24. Pangea::ResourceRegistry.register_module(Pangea::Resources::{Provider})
```

Six required sections are verified for every output (tests/compiler_guarantees.rs proof 9):
frozen pragma, require statements (>= 3), module declaration, ResourceBuilder include,
define_resource, and registry call.

### Fluent Configuration

```rust
ResourceFileBuilder::new("aws", "aws_vpc", "vpc")
    .outputs(vec![("id", "id"), ("arn", "arn")])   // override default outputs
    .map(vec!["cidr_block"])                        // direct mapping fields
    .map_present(vec!["description", "tags"])        // map_present fields
    .map_bool(vec!["enable_dns_support"])             // boolean fields
    .emit()
```

Empty categories are omitted from output. Default outputs include `id: :id`.

### Map Field Symbol Syntax

All field names in `map`, `map_present`, and `map_bool` are emitted as Ruby symbols
(`:field_name`). This is verified by proptest in tests/structural.rs proof 19 and
tests/compiler_guarantees.rs proof 20.

## RSpecBuilder

### Three Builder Types

1. **`DescribeBuilder`** -- created by `RSpecBuilder::describe()`, supports:
   - `.it(name, closure)` -- add an `it` block
   - `.context(name, closure)` -- add a nested `context` block
   - `.let_bind(name, expr)` -- add a `let` binding
   - `.it_behaves_like(name, params)` -- add shared example reference
   - `.node(ruby_node)` -- escape hatch for raw nodes
   - `.build()` -- finalize to `RubyNode::Describe`

2. **`SharedExamplesBuilder`** -- created by `RSpecBuilder::shared_examples()`, supports:
   - `.it(name, closure)` -- add an `it` block
   - `.let_bind(name, expr)` -- add a `let` binding
   - `.node(ruby_node)` -- escape hatch
   - `.build()` -- finalize to `RubyNode::SharedExamples`

3. **`ItBuilder`** -- received inside `.it()` closures, supports:
   - `.expect(subject, matcher)` -- add an expect assertion
   - `.raw(code)` -- add raw Ruby expression

### Nesting Safety

Context blocks receive a fresh `DescribeBuilder`, not the parent. This prevents
accidentally adding test cases to the wrong scope. The closure-based API makes
scope escaping a compile error.
